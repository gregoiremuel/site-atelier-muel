4Comment faire

Cloudflare n’est pas joignable depuis l’espace de Claude : tout ce qui touche à ton compte se fait avec toi. Compte 1 h à 1 h 30, hors délais d’achat et de propagation du domaine. Ne fais rien dans le désordre : le site reste en « version de travail » jusqu’à l’étape 7.

Avant de commencer : décisions
1. Nom de domaine
  1. Acheter gregoiremuel.fr et ateliermuel.fr (environ 10 € par an chacun, À VÉRIFIER le prix) à ton nom. Cloudflare ne vend pas toujours le .fr : À VÉRIFIER ; sinon OVHcloud ou Gandi.
  2. Ajouter le domaine à Cloudflare (« Add a domain », offre gratuite), changer les serveurs de noms chez le bureau d’enregistrement. Délai : quelques minutes à 24 h.
  3. Dire à Claude quand c’est actif : il ajoute la route custom_domain dans wrangler.jsonc et reglages.url dans le contenu.
2. E-mail professionnel

Recevoir : « Email Routing » de Cloudflare, gratuit (contact@gregoiremuel.fr vers ta boîte). Répondre depuis cette adresse : il faut une vraie messagerie, et certaines offres gratuites n’acceptent pas un domaine personnalisé À VÉRIFIER avant d’afficher l’adresse partout.

3. Mettre le site sur Cloudflare (depuis GitHub, sans ordinateur)
  1. dash.cloudflare.com : « Workers & Pages », « Create application », « Import a repository », choisir site-atelier-muel.
  2. Branche à déployer : la branche principale. Les changements de design du 28/10/2026 y sont fusionnés (demandes de fusion n°3 et n°4 du site et du kit).
  3. Nom du projet : site-atelier-muel exactement. « Save and Deploy ». La mémoire du site (KV) se crée toute seule.
  4. « Settings », « Variables and Secrets » : deux Secrets (pas des variables) : ADMIN_HASH et SESSION_SECRET. Demande les valeurs à Claude au moment de cette étape (npm run mot-de-passe) ; ne les écris jamais dans le dépôt. Relancer un déploiement.
  5. Adresse provisoire : site-atelier-muel.<ton-compte>.workers.dev, page de modification à la même adresse suivie de /admin.
  6. Premier essai : connexion à /admin, enregistrer une modification de test, vérifier que « Offres » affiche toujours les quatre formules et la comparaison (un défaut d’avant le 28/10, corrigé et testé), retirer le message.
4. Tester le stockage en juridiction UE (5 min, facultatif)

Dans un terminal : npx wrangler login, puis npx wrangler kv namespace create TEST-UE --jurisdiction=eu. Un identifiant s’affiche : disponible sur ton offre. Une erreur parle de bêta ou d’offre : copie le message à Claude, les textes du site ne changent pas.

À vérifier. La documentation de Cloudflare se contredit (journal du 02/10/2026 : disponibilité générale ; page de référence : bêta privée). Seul ce test fait foi. Tant que ce n’est pas fait, le site ne promet rien sur l’UE.
5. Demandes par e-mail (Web3Forms) et sauvegarde externe
  • Clé gratuite sur web3forms.com avec l’e-mail pro, à coller dans « Demandes de contact » > « Réglages du formulaire ». Sans clé, les demandes arrivent quand même dans /admin. Mettre à jour l’annexe 3 du contrat de sous-traitance avant de signer un client.
  • Copie nocturne automatique après la mise en ligne : contrôle le lendemain dans « Visites du site ». Pour une copie hors de la mémoire du site : R2 (demande peut-être une carte bancaire À VÉRIFIER), puis r2_buckets dans wrangler.jsonc.
6. Ouvrir pour de vrai
  1. Dis « go » à Claude : MAQUETTE passe à « non », route du domaine ajoutée, npm run verifier, npm test, npm run accessibilite, push.
  2. Vérifier : bandeau « version de travail » disparu, /robots.txt et /sitemap.xml en place, un envoi du formulaire arrive dans « Demandes de contact » et par e-mail.
  3. Le lendemain : « Visites du site » compte tes visites, la dernière sauvegarde est datée de la nuit.

10Référencement

Personne ne peut garantir une place dans Google, et le site le dit. Les noms de boutons de Google changent : ce qui est marqué « à vérifier » se contrôle à l’écran VÉRIFIÉ DÉPÔT pour ce que fait le site.

Ce que le site fait déjà
  • Un titre et une description différents par page, aperçu des liens partagés (Open Graph).
  • Données structurées : fiche d’entreprise sur l’accueil, questions fréquentes sur les pages par métier.
  • /robots.txt et /sitemap.xml : annoncés seulement quand MAQUETTE passe à « non » ; tant que le site est en version de travail, il est fermé aux moteurs (noindex).
  • Adresse canonique (si reglages.url est renseignée) : évite que l’adresse provisoire workers.dev et le domaine passent pour deux sites.
  • Site rapide, lisible sur téléphone, en HTTPS, sans cookie ni publicité.
Avant l’ouverture
Les cinq gestes qui comptent le plus
  1. Fiche d’établissement Google (business.google.com) : catégorie proche de « Service de création de sites Web » à vérifier dans la liste, zone « Paris 16e et à distance », téléphone, horaires, lien, photos, description honnête. Validation par vidéo, appel ou courrier à vérifier. Sans afficher ton adresse si c’est ton domicile (zone de service).
  2. Search Console : propriété « Domaine », validation DNS dans Cloudflare, envoi de https://gregoiremuel.fr/sitemap.xml, « Inspection de l’URL » de l’accueil et de chaque page par métier, « Demander une indexation ». Délai de quelques jours à quelques semaines, aucune garantie.
  3. Avis de vrais clients : tes trois pilotes d’abord. Jamais de faux avis, ni d’avis offerts contre un rabais (interdit par Google et par la loi).
  4. Mêmes nom, adresse (ou zone), téléphone et horaires partout : site, fiche, LinkedIn, Instagram, annuaires.
  5. Quelques liens depuis de vrais sites : association de commerçants du 16e, annuaires sérieux, sites de tes clients (« site réalisé par Grégoire Muel », avec accord). Pas d’achat de liens.
Autres annuaires gratuits et contenu

Suivre les résultats et ce qu’il ne faut pas faire
  • Search Console > « Performances » : chaque semaine au début. /admin > « Visites du site » (sans cookie). Fiche Google > « Performances » : appels, itinéraires, visites du site.
  • À attendre : quelques impressions dès les premières semaines, des appels via la fiche avant les premiers clics du site, un classement local correct en plusieurs mois. Si rien ne bouge après trois mois, regarde la fiche et les avis avant le code.
  • À ne pas faire : acheter liens ou avis, bourrer les pages de mots-clés, copier un autre site, promettre une place, laisser deux adresses ouvertes aux moteurs, changer des adresses de pages sans redirection.
Les deux outils de contrôle (npm run referencement et npm run look-ia)
  • npm run referencement : titre, description unique et de bonne longueur, un seul titre principal, canonique, données structurées lisibles, images avec texte alternatif, liens internes, quantité de texte. Sort en erreur si une page a un défaut qui gêne Google. npm run referencement -- --en-ligne https://adresse-du-site contrôle aussi robots.txt et sitemap.xml du site publié.
  • npm run look-ia : repère texte à la première personne, formules toutes faites, couleur d’accent trop vive, dégradés, coins arrondis, pages trop longues. Indice, pas un juge : un avis extérieur de sous-agents sur captures a jugé le site à 6,5/10 avant la dernière révision, ce qui a conduit à retirer le motif décoratif répété sur chaque page AVIS SIMULÉ.
  • À relancer après chaque changement important, avec npm run verifier et npm test.
